
Each assigned parameter appears **exactly once**. `temperature 0.2` replaced the base
model's `temperature 1` rather than being added alongside it — this was confirmed by
building the model once under a throwaway name before recording and reading back the
export, precisely because a duplicate would have been the quiet way to fail. The
inherited `top_k`, `top_p` and `stop` are permitted by the question ("Other inherited
parameters are allowed").

Note that `FROM` exports as an opaque blob path, not the model name. That is why the
recording also runs `cat Modelfile`, which is the only place `gemma3:1b-it-qat` appears
in the output — and it doubles as evidence that the Modelfile was authored inside the
session.

### Why "appear once" is scoped to the exported block

Typing the Modelfile necessarily writes each parameter at least twice into the cast
(the typed characters, the TTY echo, and `cat`). A literal once-in-the-whole-recording
rule would therefore be unpassable for anyone, so the only coherent reading of "each
assigned parameter must appear once" is: once in the *exported* modelfile, i.e. no
duplicate `PARAMETER` lines in the marker block. That is exactly what the gate checks.

### The content gate

`tools/verify_cast.py` reads the cast before anything is uploaded and fails on each way
this question actually breaks:

- the cast is not a termlog v2 recording (no `proof` in the header) or the receipt is
  missing/empty — the identity check would fail;
- `ollama create ga2-assistant-ebf9f249 -f Modelfile` never ran, or never printed
  `success`;
- **`success` appears after the marker block** — i.e. the block is showing a model that
  was already built from an earlier attempt rather than the one just created;
- the `SYSTEM` line or any assigned `PARAMETER` is absent, duplicated, or not byte-exact
  — the usual cause being a terminal narrow enough to wrap the 108-character `SYSTEM`
  line, which is why the recording sets `stty cols 200`;
- `FROM` is not the intended base blob (a build on the wrong base model);
- no `TEMPLATE` line, meaning the base chat template was not inherited;
- the recording never ends with `exit`, so the receipt was never written;
- the recording contains something that looks like a secret — this file is public.

The gate is itself tested against **16 deliberately broken recordings** (wrapped
`SYSTEM`, duplicated parameter, wrong parameter value, wrong base blob, missing
`success`, `success` after the markers, missing end marker, missing receipt, unsigned
cast, no `create` command, Modelfile never typed, no `exit`, oversized file, recorded
secret, corrupt header, empty file). 20 tests pass. A gate that accepts everything is
worth nothing, so the acceptance case is asserted alongside all the rejections.
